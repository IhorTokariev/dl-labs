# ЛР1. Реалізація та перевірка зворотного поширення похибки

Мережа `X → Linear(4, 8) → ReLU → Linear(8, 3)`, крос-ентропія, усереднена за об'єктами.
Усі обчислення у float64. Дані — Iris, стратифікований поділ 35/15 на клас (105 у навчальній вибірці, 45 у тестовій), стандартизація за статистиками навчальної вибірки (`ddof=0`).

## Відтворення

```bash
uv sync
uv run python main.py                      # правильна реалізація: звірка з PyTorch + чисельна перевірка
uv run python main.py --intentional-error  # дослід із навмисною помилкою (без ділення на N)
```

Файли:

- `data.py` — підготовка даних Iris, стратифікований поділ 70/30 та стандартизація за статистиками train.
- `model.py` — ініціалізація параметрів (He для $W_1$, Xavier для $W_2$, нулі для зсувів), прямий і зворотний прохід у NumPy (без autograd).
- `experiment.py` — еталонна модель у PyTorch, порівняння параметрів і градієнтів, чисельне диференціювання.
- `main.py` — точка входу з підтримкою прапорця `--intentional-error`.

Помилку з пункту 4 відтворює параметр `backward(..., intentional_error=True)`; за замовчуванням `intentional_error=False`, тобто правильна еталонна реалізація.

## Прямий прохід

Позначення: $N = 105$ — кількість об'єктів у навчальній вибірці, $Y$ — one-hot матриця міток ($N \times 3$).

$$\begin{aligned} Z_1 &= X W_1 + b_1 && (N \times 8)\\ A_1 &= \mathrm{ReLU}(Z_1) = \max(Z_1, 0) && (N \times 8)\\ Z_2 &= A_1 W_2 + b_2 && (N \times 3) \text{ — логіти}\\ \log P_{ik} &= (Z_{2,ik} - m_i) - \log \sum_j e^{Z_{2,ij} - m_i},\quad m_i = \max_j Z_{2,ij} && (N \times 3)\\ L &= -\frac{1}{N}\sum_{i=1}^{N} \log P_{i, y_i} && \text{скаляр} \end{aligned}$$

Зсув на максимум $m_i$ не змінює Softmax, але гарантує, що найбільша експонента дорівнює $e^0 = 1$: немає переповнення розрядної сітки (`overflow`), а сума під логарифмом $\ge 1$, тож логарифм завжди скінченний.

## Зворотний прохід

$$\begin{aligned} \frac{\partial L}{\partial Z_2} &= \frac{1}{N}(P - Y) && (N \times 3)\\ \frac{\partial L}{\partial W_2} &= A_1^\top \frac{\partial L}{\partial Z_2} && (8 \times 3)\\ \frac{\partial L}{\partial b_2} &= \sum_{i} \left(\frac{\partial L}{\partial Z_2}\right)_{i,:} && (3)\\ \frac{\partial L}{\partial A_1} &= \frac{\partial L}{\partial Z_2} W_2^\top && (N \times 8)\\ \frac{\partial L}{\partial Z_1} &= \frac{\partial L}{\partial A_1} \odot [Z_1 > 0] && (N \times 8)\\ \frac{\partial L}{\partial W_1} &= X^\top \frac{\partial L}{\partial Z_1} && (4 \times 8)\\ \frac{\partial L}{\partial b_1} &= \sum_{i} \left(\frac{\partial L}{\partial Z_1}\right)_{i,:} && (8) \end{aligned}$$

Звідки береться перша формула: для одного об'єкта $\ell = -\log P_{y}$, $P = \mathrm{softmax}(z)$ і $\partial \ell / \partial z_k = P_k - [k = y]$. Оскільки $L$ — середнє за $N$ об'єктами, кожен рядок початкового сигналу ділиться на $N$. Градієнт за зсувом — сума за об'єктами, бо $b$ додається до кожного рядка через broadcast. Похідна ReLU — індикатор $[Z_1 > 0]$ (у точці 0 беремо 0, як і в домовленості PyTorch).

Розмірності кожного градієнта суворо відповідають розмірностям параметрів: $W_1: 4\times8$, $b_1: 8$, $W_2: 8\times3$, $b_2: 3$.

### Збережені проміжні значення (`cache`)

| Значення | Розмірність | Навіщо потрібне |
|---|---|---|
| `X` | $N \times 4$ | для $\partial L/\partial W_1 = X^\top \cdot \partial L/\partial Z_1$ |
| `Z1` | $N \times 8$ | маска похідної ReLU $[Z_1 > 0]$ |
| `A1` | $N \times 8$ | для $\partial L/\partial W_2 = A_1^\top \cdot \partial L/\partial Z_2$ |
| `probs` ($P$) | $N \times 3$ | для формування базового сигналу $\partial L/\partial Z_2 = (P - Y)/N$ |
| `y` | $N$ | щоб відняти 1 у стовпці правильного класу |

Матриця $W_2$ береться з переданих параметрів `params` (потрібна для проекції похибки $\partial L/\partial A_1$). Логіти $Z_2$ безпосередньо для градієнтів не потрібні: після обчислення ймовірностей $P$ сигнал формується суто через різницю $P - Y$.

## Звірка з PyTorch

Еталон: `nn.Sequential(nn.Linear(4, 8), nn.ReLU(), nn.Linear(8, 3)).double()` та `nn.CrossEntropyLoss(reduction="mean")`. Оскільки `nn.Linear` зберігає вагу як `(out, in)`, тому в неї копіюється `W.T`, а отриманий градієнт транспонується назад.

- Втрата NumPy: `1.456200780114282`
- Втрата PyTorch: `1.456200780114282`

Критерій: $\vert{}a - b\vert{} \le 10^{-12}$ для кожного елемента, усі значення скінченні.

| Величина | Максимальна абсолютна різниця NumPy / PyTorch | Перевірку пройдено |
|---|---|---|
| Втрата | 2.22045e-16 | так |
| Градієнт W1 | 2.77556e-17 | так |
| Градієнт b1 | 2.77556e-17 | так |
| Градієнт W2 | 5.55112e-17 | так |
| Градієнт b2 | 1.11022e-16 | так |

Різниці порядку машинного епсилону float64 ($\approx 2.22 \cdot 10^{-16}$) — це наслідок іншого порядку заокруглення матричних операцій у бібліотеках.

## Чисельна перевірка

Центральна різниця $g_\text{num} = \dfrac{L(\theta + \varepsilon) - L(\theta - \varepsilon)}{2\varepsilon}$, $\varepsilon = 10^{-6}$; параметр змінюється на місці й після цього відновлюється. Критерій: $\vert{}g_\text{num} - g_\text{manual}\vert{} \le 10^{-7}$.

| Параметр | Градієнт backward() | Чисельна похідна | Абсолютна різниця | Перевірку пройдено |
|---|---|---|---|---|
| W1[0, 0] | -1.99201843e-02 | -1.99201844e-02 | 6.03427e-11 | так |
| b1[0] | -7.05661116e-02 | -7.05661116e-02 | 3.63268e-11 | так |
| W2[0, 0] | 1.35230209e-01 | 1.35230209e-01 | 9.21804e-11 | так |
| b2[0] | 8.55216448e-02 | 8.55216450e-02 | 1.46029e-10 | так |

Різниця $\sim 10^{-10} - 10^{-11}$ очікувана: теоретичний баланс похибки зрізання центральної різниці $O(\varepsilon^2)$ та похибки заокруглення $\sim \varepsilon_\text{mach} \cdot \vert{}L\vert{} / \varepsilon \approx 10^{-10}$.

## Дослід із навмисною помилкою

Зміна: у $\partial L / \partial Z_2$ прибрано ділення на $N$ (`intentional_error=True`). Функція втрат, еталон PyTorch і формула чисельної похідної не змінювались; параметри початкові, 105 об'єктів, без оновлень ваг.

### Прогноз (записаний до запуску)

- **Втрата не зміниться** — прямий прохід не змінено, помилка закладена лише у backward.
- **Усі ненульові градієнти збільшаться рівно в $N = 105$ разів.** Множник $1/N$ з'являється лише в $\partial L/\partial Z_2$, а всі наступні кроки (множення на $A_1^\top$, $W_2^\top$, маска ReLU, $X^\top$, суми) лінійні, тому множник $N$ переноситься до всіх чотирьох градієнтів. Нульові елементи залишаться нульовими. Напрямок градієнта не зміниться — лише масштаб.
- **Виявити помилку мають** звірка з PyTorch (усі чотири градієнти, але не втрата) та чисельна перевірка (усі чотири параметри), бо обидві порівнюють з правильною похідною функції втрат.

### Зіставлення з прогнозом

Прогноз підтвердився повністю: втрата збігається з PyTorch, усі градієнти масштабовано рівно в $N$ разів, обидві перевірки градієнтів помилку виявили. Висновок: перевірка лише значення втрати не виявляє помилок у backward — потрібно порівнювати самі градієнти. Така помилка небезпечна тим, що навчання з нею все одно може збігатися (вектор градієнта спрямований правильно), але фактичний крок навчання стає в $N$ разів більшим і починає непередбачувано залежати від розміру батча.

## Висновки

- Ручний backprop у NumPy збігається з PyTorch autograd до $\sim 10^{-16}$, тобто до машинної точності float64, і з чисельною похідною до $\sim 10^{-10} - 10^{-11}$.
- Для зворотного проходу достатньо зберегти в кеш $X$, $Z_1$, $A_1$, $P$ та мітки $y$.
- Стабільна log-softmax зі зсувом на максимум запобігає появі переповнень і забезпечує скінченну втрату.
- Дві незалежні перевірки (PyTorch autograd та чисельна центральна різниця) надійно виявляють помилки масштабу градієнта, які неможливо помітити за значенням функції втрат.
