# ЛР1. Реалізація та перевірка зворотного поширення похибки

У межах лабораторної роботи реалізовано двошарову повнозв'язну нейронну мережу з архітектурою `4 → 8 (ReLU) → 3 (Log-Softmax)`. Цільова функція — середнє значення категоріальної крос-ентропії (Categorical Cross-Entropy Loss).
Усі обчислення виконуються з машинною точністю `float64`. Набір даних — класичний датасет Iris Fisher. Вибірку поділено стратифіковано у співвідношенні 70/30 (по 35 навчальних та 15 тестових прикладів для кожного з трьох класів: 105 у train, 45 у test). Ознаки нормалізовано (Z-score стандартизація) виключно за статистиками (`mean`, `std` з `ddof=0`) тренувального набору.

## Відтворення

```bash
uv sync
uv run python main.py                      # базовий запуск: валідація проти PyTorch autograd та перевірка градієнтів
uv run python main.py --intentional-error  # експеримент зі штучно внесеним дефектом у backward (пропуск масштабування на N)
```

Структура модулів:

- `data.py` — завантаження датасету Iris, стратифіковане розбиття вибірки та стандартизація ознак на основі тренувальних метрик.
- `model.py` — ініціалізація ваг (схема He для $W_1$, Glorot/Xavier для $W_2$, нульові bias-вектори), явна реалізація forward та backward проходів мовою NumPy без autograd.
- `experiment.py` — побудова аналогічної архітектури засобами PyTorch, процедури покомпонентного порівняння ваг і градієнтів, чисельна апроксимація похідних.
- `main.py` — головний скрипт виконання тестувань із підтримкою прапорця `--intentional-error`.

Логіка некоректного градієнта активується через аргумент функції `backward(..., intentional_error=True)`. За умовчанням використовується `intentional_error=False` (коректний аналітичний розрахунок).

## Прямий прохід

Позначення: $N = 105$ — кількість об'єктів у навчальній вибірці, $Y$ — one-hot матриця міток ($N \times 3$).

$$\begin{aligned} Z_1 &= X W_1 + b_1 && (N \times 8)\\ A_1 &= \mathrm{ReLU}(Z_1) = \max(Z_1, 0) && (N \times 8)\\ Z_2 &= A_1 W_2 + b_2 && (N \times 3) \text{ — логіти}\\ \log P_{ik} &= (Z_{2,ik} - m_i) - \log \sum_j e^{Z_{2,ij} - m_i},\quad m_i = \max_j Z_{2,ij} && (N \times 3)\\ L &= -\frac{1}{N}\sum_{i=1}^{N} \log P_{i, y_i} && \text{скаляр} \end{aligned}$$

Для запобігання арифметичному переповненню розрядної сітки (`overflow`) обчислення логарифмів імовірностей виконується за стабілізованою схемою Log-Sum-Exp. Віднімання векторного максимуму логітів $m_i = \max_j Z_{2,ij}$ математично інваріантне щодо значення Softmax, однак гарантує, що максимальний степінь експоненти не перевищує 0 ($e^0 = 1$). Відповідно, аргумент логарифма завжди $\ge 1$, що унеможливлює появу значень `inf` або `NaN`.

## Зворотний прохід

$$\begin{aligned} \frac{\partial L}{\partial Z_2} &= \frac{1}{N}(P - Y) && (N \times 3)\\ \frac{\partial L}{\partial W_2} &= A_1^\top \frac{\partial L}{\partial Z_2} && (8 \times 3)\\ \frac{\partial L}{\partial b_2} &= \sum_{i} \left(\frac{\partial L}{\partial Z_2}\right)_{i,:} && (3)\\ \frac{\partial L}{\partial A_1} &= \frac{\partial L}{\partial Z_2} W_2^\top && (N \times 8)\\ \frac{\partial L}{\partial Z_1} &= \frac{\partial L}{\partial A_1} \odot [Z_1 > 0] && (N \times 8)\\ \frac{\partial L}{\partial W_1} &= X^\top \frac{\partial L}{\partial Z_1} && (4 \times 8)\\ \frac{\partial L}{\partial b_1} &= \sum_{i} \left(\frac{\partial L}{\partial Z_1}\right)_{i,:} && (8) \end{aligned}$$

Обґрунтування аналітичних виразів:
1. Похідна крос-ентропійної втрати одного спостереження за вихідними логітами має вигляд $\partial \ell / \partial z_k = P_k - [k = y]$. Враховуючи, що цільова функція втрат $L$ є вибірковим середнім за $N$ прикладами, початковий сигнал помилки масштабується множником $1/N$.
2. Градієнти за векторами зсуву $b_1$ та $b_2$ формуються агрегацією вздовж вибіркової осі (batch axis), оскільки зміщення транслюється (broadcast) на всі спостереження.
3. Субградієнт функції активації ReLU визначено через індикатор $[Z_1 > 0]$, де в нульовій точці прийнято значення 0 (згідно зі стандартом реалізації в PyTorch).
4. Розмірності отриманих матриць і векторів градієнтів строго узгоджуються з просторами відповідних оптимізованих параметрів: $W_1: 4\times8$, $b_1: 8$, $W_2: 8\times3$, $b_2: 3$.

### Збережені проміжні значення (`cache`)

| Значення | Розмірність | Навіщо потрібне |
|---|---|---|
| `X` | $N \times 4$ | для $\partial L/\partial W_1 = X^\top \cdot \partial L/\partial Z_1$ |
| `Z1` | $N \times 8$ | маска похідної ReLU $[Z_1 > 0]$ |
| `A1` | $N \times 8$ | для $\partial L/\partial W_2 = A_1^\top \cdot \partial L/\partial Z_2$ |
| `probs` ($P$) | $N \times 3$ | для формування базового сигналу $\partial L/\partial Z_2 = (P - Y)/N$ |
| `y` | $N$ | щоб відняти 1 у стовпці правильного класу |

Вектор ваг $W_2$ передається у зворотний прохід із поточного стану параметрів моделі `params` (необхідний для зворотного прокидання похибки на прихований шар через $\partial L / \partial A_1$). Самі сирі логіти $Z_2$ у кеші не дублюються, оскільки для знаходження градієнта вихідного шару достатньо мати розраховані ймовірності $P$ та вектори міток $y$.

## Звірка з PyTorch

Для верифікації розробленої моделі створено еквівалентний пайплайн на PyTorch: послідовна мережа `nn.Sequential(nn.Linear(4, 8), nn.ReLU(), nn.Linear(8, 3)).double()` у парі з критерієм `nn.CrossEntropyLoss(reduction="mean")`. Зважаючи на конвенцію PyTorch про зберігання матриць ваг у форматі `(out_features, in_features)`, ваги $W$ перед передачею копіюються як `W.T`, а отриманий тензор градієнта транспонується назад.

- Втрата NumPy: `1.456200780114282`
- Втрата PyTorch: `1.456200780114282`

Критерій успішності: $\vert{}a - b\vert{} \le 10^{-12}$ для кожного елемента, усі значення скінченні.

## Чисельна перевірка

Перевірка коректності аналітичного диференціювання здійснювалася методом центральних скінченних різниць:
$$g_\text{num} = \dfrac{L(\theta + \varepsilon) - L(\theta - \varepsilon)}{2\varepsilon},\quad \varepsilon = 10^{-6}$$
Модифікація значень параметрів виконувалася на місці з обов'язковим подальшим відновленням. Критерій проходження тесту: $\vert{}g_\text{num} - g_\text{manual}\vert{} \le 10^{-7}$.

| Параметр | Градієнт backward() | Чисельна похідна | Абсолютна різниця | Перевірку пройдено |
|---|---|---|---|---|
| W1[0, 0] | -1.99201843e-02 | -1.99201844e-02 | 6.03427e-11 | так |
| b1[0] | -7.05661116e-02 | -7.05661116e-02 | 3.63268e-11 | так |
| W2[0, 0] | 1.35230209e-01 | 1.35230209e-01 | 9.21804e-11 | так |
| b2[0] | 8.55216448e-02 | 8.55216450e-02 | 1.46029e-10 | так |

Отримана розбіжність порядку $10^{-10} - 10^{-11}$ повністю узгоджується з теоретичним компромісом між похибкою апроксимації схеми $O(\varepsilon^2) \sim 10^{-12}$ та похибкою машинного заокруглення $\sim \varepsilon_\text{mach} \cdot \vert{}L\vert{} / \varepsilon \approx 10^{-10}$.

## Дослід із навмисною помилкою

Характер модифікації: у виразі для $\partial L / \partial Z_2$ навмисно вилучено нормалізацію на кількість прикладів $N$ (`intentional_error=True`), що еквівалентно розрахунку градієнта сумарної, а не усередненої втрати. Реалізація forward pass, еталонна модель PyTorch та чисельний дифтест залишилися незмінними; ваги моделі не оновлювалися.

### Теоретичний прогноз (сформульований до запуску)

1. **Значення функції втрат:** залишиться абсолютно ідентичним, оскільки прямий прохід мережі не зазнав змін, а дефект внесено виключно у backward.
2. **Масштабування градієнтів:** усі ненульові компоненти градієнтів мають зрости рівно в $N = 105$ разів. Оскільки операції поширення градієнта через лінійні шари, ReLU-маскування та агрегацію зміщень є лінійними операторами, відсутній дільник $N$ на першому кроці транслюється на всі 4 градієнти без зміни їхнього напрямку в просторі параметрів.
3. **Чутливість методів контролю:** помилку повинні безпомилково зафіксувати як зіставлення з PyTorch autograd, так і метод центральних різниць (у частині градієнтів), тоді як перевірка за значенням Loss тест пройде.

### Зіставлення з прогнозом

Експеримент повністю підтвердив теоретичні очікування: значення Loss збігається з PyTorch, тоді як градієнти пропорційно завищені в $N$ разів.
Аналіз наслідків дефекту:
- Контроль тільки за значенням функції втрат є принципово недостатнім для валідації алгоритмів оптимізації, оскільки коректний forward pass маскує критичні збої у backward pass.
- Така системна помилка є небезпечною на практиці: оскільки кутовий напрямок градієнтного вектора не спотворюється, процес навчання все одно може збігатися. Проте ефективний крок оптимізації збільшується в $N$ разів і стає жорстко залежним від розміру вибірки, що при зміні batch size призведе до раптової розбіжності градієнтного спуску.

## Висновки

1. **Точність ручної реалізації:** розраховані аналітичні градієнти в середовищі NumPy демонструють збіжність з еталоном PyTorch до рівня машинної похибки подвійної точності ($\sim 10^{-16}$), а також підтверджені скінченно-різницевою апроксимацією з відхиленням не більше $\sim 10^{-10} - 10^{-11}$.
2. **Оптимальність збереження стану:** визначено мінімально необхідний контекст прямого проходу ($X, Z_1, A_1, P, y$), достатній для точного відновлення градієнтів усіх параметрів без надлишкових витрат оперативної пам'яті.
3. **Обчислювальна стійкість:** застосування числово-стабільного Softmax через віднімання координатного максимуму гарантує коректне обчислення логарифмів імовірностей та виключає виникнення числових аномалій (NaN/Inf).
4. **Методологія контролю якості:** емпірично доведено, що моніторинг виключно скалярної величини Loss не дозволяє діагностувати помилки зворотного поширення. Для верифікації моделей обов'язковим є пряме покомпонентне порівняння градієнтних тензорів.
